# Dead Space 3 — Linux и Android из одного дерева

Основа — Linux №75. `runtime/` и `settings/` общие; один `Makefile` компилирует их отдельно для x86‑64 и ARM64. `linux/` — SDL2, оконная система, лаунчер и звуковые выходы. `android/` — лаунчер, сенсорное управление №52, JNI и упаковка APK. Слепков `gen*`, готовых объектников и гостевого кода в этом дереве нет.

```bash
./build-linux.sh
KEYSTORE=/путь/к/локальному/ds3port-debug.keystore ./build-android.sh
```

По умолчанию локальные входы читаются из `../build-inputs`, результаты идут в `../build-output/linux` или `../build-output/android`. Можно задать `DS3_INPUTS=/абсолютный/путь` и передать другой каталог результата первым аргументом. Каталог результата можно указывать повторно: если в нём лежит прошлая сборка (есть `SHA256SUMS` и бинарник или APK), файлы перезаписываются на месте, а лишние артефакты прошлой сборки удаляются. Непустой посторонний каталог, корень проекта и домашний каталог отклоняются. `JOBS` по умолчанию равен `nproc`. Скрипты не устанавливают и не публикуют сборки. При прямом вызове `make` задавайте отдельный `BUILD` для каждого набора входов и инструментов; скрипты делают это автоматически.

- **Linux x86‑64:** GNU make, C-компилятор, `pkg-config`, SDL2 ≥ 2.26, Python 3. Нужны `linux/{base,wide,dispatch}` — аттестованный гостевой C №75, а также `linux-x86_64/{image.bin,libme1spv.so}` и заголовки PipeWire/SPA в `pipewire-headers/`. Все `.o` компилируются заново. После сборки: `../build-output/linux/ds3-launcher`.
- **Android ARM64, Android 10+:** GNU make, NDK r27c, JDK 17, SDK Platform 34, Build Tools 34.0.0, `zip`. Использует **тот же** комплект гостевого C №75 (`linux/{base,wide,dispatch}`) и `linux-x86_64/image.bin`. Дополнительно нужны ARM64 `android-arm64/libme1spv.so` и существующий `KEYSTORE`. `NDK`, `ANDROID_SDK`, `ANDROID_BT`, `ANDROID_JAR` и `JAVA_HOME` можно переопределить. Результат — `../build-output/android/ds3port.apk`.

Название `linux/` у приватных гостевых входов историческое: обе цели компилируют один и тот же набор C-файлов в машинный код своей платформы. Игровые образы, generated C, SPIR-V библиотеки и ключ остаются локальными и не входят в дерево исходников.

## Настройки порта

Лаунчер пишет `<docs>/ds3port.ini` и больше ничего не передаёт: ни аргументов, ни переменных окружения. Рантайм сам читает этот файл при старте (`ds3cfg_apply_env` в `settings/ds3settings.c`, вызов из `ds3_main` до `gm_ds3_config`) и переводит поддерживаемые ключи в переменные, которые читают `main_ds3.c`, `gearmass.c` и `hle_d3d9_gl.h`. Явно заданная переменная окружения имеет приоритет над файлом, поэтому поле «Доп. переменные» в лаунчере по-прежнему перекрывает настройки.

`--docs` необязателен: без него рантайм берёт `$XDG_DATA_HOME/ds3port/Documents`, иначе `~/.local/share/ds3port/Documents` — тот же путь, что и лаунчер. Лаунчер передаёт `--docs` только для нестандартного профиля, поэтому обычный запуск — это `ds3-wayland --game DIR --lang ru`.

`DS3_IMAGE` тоже необязателен: без него рантайм берёт `image.bin` рядом с исполняемым файлом (так он лежит в `build-output/linux/`), а если его там нет — `out/exe/image.bin` для дерева сборки.

Так же устроен порт Mass Effect: `me1cfg_load` читает `me1port.ini` внутри рантайма. Список ключей — только те, что действительно потребляются: `FpsLimit`, `ShowFps`, `Gearmass`, `GearmassAutoResolution`, `GearmassHud`, `GearmassThermal`, `GearmassWorkers`, `GearmassAhead`, `GearmassSpin`, `GearmassPrime`, `GearmassAniso`, `StretchMode`. `SimpleShaders`, `PhoneModify` и сенсорные опции в схему DS3 не попадают: рантайм их игнорирует.

## Проверка полноты рекомпиляции

Рекомпилятор находит функции по прямым вызовам, экспортам и таблицам; цель, до которой он не дошёл, остаётся без тела `ds3_<va>`. Прямой вызов тогда ломает линковку, а косвенный (через указатель) останавливает рантайм на `dispatch: no function at target`. Проверка сверяет таблицу `ds3_funcs` из `dispatch/module.c` с образом `image.bin` и сгенерированным C:

```bash
make INPUTS=/абсолютный/путь/к/build-inputs check-funcs
```

Точные проверки (падение — ошибка сборки): адрес и символ каждой записи совпадают и лежат в `.text`; у каждой ссылки `ds3_<va>(c)` есть запись; цель каждого `call 0x…` — запись таблицы или локальная метка той же функции. Эвристика (предупреждение): 4-байтовое значение в `.rdata`/`.data` указывает в `.text`, записи нет, тела нет, а по адресу стоит пролог функции — так выглядит функция, до которой можно дойти только через vtable.

Найденные адреса выгружаются в файл для `recomp.py --seeds`:

```bash
python3 -B runtime/check_ds3_funcs.py ../build-inputs/linux-x86_64/image.bin ../build-inputs/linux --seeds-out=runtime/ds3_extra_seeds.txt
```

Текущий результат на аттестованном наборе №75: 65 255 записей, 26 150 целей вызовов, 27 680 ссылок `ds3_` — расхождений нет; эвристика даёт 9 адресов, они лежат в `runtime/ds3_extra_seeds.txt`.
